# 文筆守門員 Tone Guard

## 這是什麼

一套在 AI 寫中文的時候自動攔截的檢查程式。它掛在 Claude Code 的掛勾上，
AI 每一次要改檔案、發留言、提交版本、把事情交辦出去、或是回話，
都要先過一次這裡的檢查。

它不是第 201 條規則。規則是文字，讀到不等於照做；這裡的東西是程式，不過就是不過。

## 它能幫你做到什麼

先講統計出來的數字，因為它推翻了原本的直覺。

近一個月 Vin 發出 964 則訊息，其中 39 則在抱怨產出品質：

| 抱怨的種類 | 則數 | 佔比 |
|---|---|---|
| 聽不懂、看不懂 | 26 | 67% |
| 該跑的檢查沒跑 | 5 | 13% |
| 內容零碎、太長 | 3 | 8% |
| 文案寫得爛 | 2 | 5% |
| 不像台灣人寫的 | 2 | 5% |
| 用了自己發明的詞 | 1 | 3% |

**三分之二的抱怨是「聽不懂」，用詞問題只佔 3%。**
再往下查那 26 則，發現問題幾乎都不在文筆，而是**他問的那件事沒有被回答**：
他問一句短的是非題，回覆卻是一份工作過程的交代。

所以這套程式的目標不是把句子潤順，是讓回覆先回答問題。

## 你現在要做什麼

```bash
bash install.sh
```

它會把這個 repo 的掛勾連進 `~/.claude/hooks`，再把規則與語料資料夾連進 `~/.claude`。
安裝完之後要自己在 `~/.claude/settings.json` 把五個掛勾掛上去，`install.sh` 會印出要貼的內容。

## 兩層檢查，各擋不同的東西

| 層 | 程式 | 擋什麼 | 目前的涵蓋率 |
|---|---|---|---|
| 第一層 掃詞 | `hooks/coined_word_guard.py` | 白紙黑字的用詞：自創量詞、口語動詞、比喻、把機器狀態講成人的動作 | 抓得到 Vin 實際退稿句子的 25%，詞表 47 個一律擋、9 個只提醒 |
| 第二層 讀意思 | `hooks/copy_judge.py` | 他問的那件事有沒有被回答 | 還在調，目前只提醒不擋 |

### ToneGuard：輸入框上面那一行，看得出這一輪有沒有檢查過

掃詞跟讀意思這兩層，只有真的擋人的時候才出聲，沒擋就一片安靜。畫面一片安靜的時候，
Vin 分不出這一輪是真的沒問題，還是根本沒被檢查到。
所以輸入框上面多了一行，判斷寫在最前面，後面才寫這一輪碰到哪幾份中文：

```
ToneGuard  文法檢查通過・16 個檔、PR 內文（01:12、01:15）
ToneGuard  polish 沒跑・5 個檔、issue 留言・擋下 2 條          ✕
ToneGuard  還沒檢查・draft-zh.md、index.html                  ✕
```

三種顏色各代表一件事：

| 顏色 | 代表什麼 | 你要做什麼 |
|---|---|---|
| 綠色 | 兩個 skill 都跑過了 | 不用管 |
| 黃色 | 還沒檢查，或只跑了一個 | 等它跑完 |
| 紅色 | 有指令真的被擋下來，那句話沒有送出去 | 看一下它擋的是哪一句 |

檔名最多列兩個名字，再多就只寫數量 —— 一次碰十幾個檔的時候全部列出來，
會排滿五行，而判斷就被擠到最後面。視窗窄到排不下的時候那一行會被截斷，不會換行。
我回完話 5 秒後它自己收起來，三種顏色都一樣。

程式在 `mods/copy-gate/`，安裝之後連到 `~/.claude/mods/copy-gate`，
而且要在 `~/.claude/settings.json` 的 `env` 裡把那個路徑列進 `CLAUDE_CODE_PLUGIN_DIRS`，
那一行才會出現。它只負責顯示，真正擋人的是 `hooks/copy_gate_on_edit.py`。

輸入框上面那一行判斷哪幾份是要給人讀的中文，規則是從 `hooks/copy_gate_on_edit.py`
與 `hooks/coined_word_guard.py` 複製過來的。只改 python 那兩支的話，擋下來的指令會變，
那一行顯示的顏色卻不會跟著變，所以兩邊要在同一個提交裡一起改。

### 掃詞掛在哪裡：預設全掃，例外才放行

原本是名單制，程式先問「這個工具在不在我的名單上」，在名單上才掃。
每多一個出口就要多加一條，而且永遠不知道還有幾個沒加到 ——
2026-09-15 實測就抓到三個：`gh issue comment -b` 的短旗標、`-F` 指到的內文檔，
以及用 `gspread` 把工作日誌寫進 Google 試算表。

現在反過來：**每一個工具動之前都先掃，掃到連續的中文就當成文案，例外才列名單。**
掛勾的比對規則寫成 `.*`，以後接的任何新工具也一樣涵蓋得到。

| 這次要做的事 | 掃不掃 |
|---|---|
| 改檔案、開 artifact、把事情交給別人做、回話 | 掃 |
| `gh` 開單與留言、`git commit`、寄信、寫進 Google 試算表或線上文件 | 掃 |
| 用 `cat`、`tee`、`echo` 把中文寫進專案裡的檔案 | 掃 |
| 沒見過的工具（包含以後接的 MCP） | 掃 |
| 讀檔、搜尋、跑這個 repo 自己的檢查程式 | 不掃 |
| 寫進暫存目錄的東西 | 不掃 |

認不出是哪一種情境、可是真的要給人讀的，會記一筆到
`~/.claude/state/copy-gate/unmatched.jsonl`。那份紀錄就是「還有哪幾種情境沒進目錄」的清單。

**指令裡有中文，不等於那段中文會被人讀到。** 2026-10-03 把累積的 2,968 筆分類過，
86% 是拿中文去搜尋、echo 給自己看、或行內腳本自己的字串。那種紀錄留著只會把真的缺口蓋掉，
所以現在要先認得出有讀者才記。用指令把字寫進檔案的時候，情境照那個檔案的路徑認。

### 寫給 agent 讀的文件走另一套規則

在檔案開頭加一行 `audience: agent`，掃詞就改用 `copy-samples/agent-doc-rules.json`。
沒寫的一律當成人要讀。

那一行要寫在檔案的前 400 個字、前 5 行、而且在第一個程式碼區塊之前。
**認的是檔案上的宣告，不是這次要寫進去的那段字** —— 不然只要在要送出去的文字
最前面加一行，這段字就自己把自己放行了。回話與交辦沒有檔案可讀，一律照人那一套。

兩套分開的理由是讀者會被不同的東西絆倒。人讀到自創詞會停下來猜，猜錯就理解錯；
agent 照字面處理，不會因為用詞不像台灣人就少做一步。它會做錯的是別的地方：

| agent 那一套擋什麼 | 擋還是提醒 |
|---|---|
| 條件寫得不明確：盡量、適當、視情況、原則上、自行判斷 | 擋。agent 會自己決定放寬到什麼程度 |
| 同一個東西前後兩個名字：測試機／測試環境、app／應用程式 | 提醒。它會當成兩件事 |
| 實測數字沒標明是參考值還是要追的目標 | 提醒。它會把別人的數字當成自己的目標 |

比對名稱是否前後一致的時候，程式碼區塊與行內的指令、檔名都先拿掉 ——
內文寫「分支」而指令裡有 `branch`，那不是前後不一致。

**名字怎麼分：整套東西叫文筆守門員，第一層叫掃詞，第二層叫語意判官。**
第二層管的是「這段有沒有回答讀者的問題」，跟第一層掃用詞是兩件事，所以名字也分開。

第一層是正則加詞表，對錯沒有爭議，所以它可以直接擋。
第二層要另一個模型讀「他問的那一句」加上「AI 的回覆」。
**它自己也會判錯，所以它要先考過試才准擋人**，見下面「怎麼考語意判官」。

問它「這一段有多難讀，給 0 到 10 分」行不通。不管問哪一個模型，它幾乎每一段都回
7 分或 8 分，所以門檻訂在哪裡結果都一樣，考題上也分不出好壞。
改成兩份稿一起送進去、問哪一份比較難讀，同一個模型就分對八對（九對裡）。

所以第二層只在手上有兩份稿可以比的時候出手：**他說看不懂、AI 重寫一版的時候，
把他退掉的那一份跟重寫的這一份一起送進去。** 判官說重寫的那一份還比較難讀，
就當場擋下來，重寫過再送。這個時候「爛的那一份」是他親口退掉的，不是猜的。

另外三支各管一件事：

| 程式 | 做什麼 |
|---|---|
| `hooks/copy_gate_on_edit.py` | 這次編輯有沒有動到引號裡的中文。有的話，這一輪沒跑過文案 skill 就擋住。要 commit、開單留言、發到 pages 的中文檔，沒有審用詞的回執也擋住 |
| `hooks/agy_review.py` | 送出前把中文檔交給另一個模型審用詞，審過留回執。回執認內容的 sha256，改過就要再審 |
| `hooks/copy-voice-inject.py` | 每一輪把 Vin 自己寫過的句子送進 context，同時存下他這一句。AI 回完話再把這一輪寫出去的中文記兩天，他下次貼回來的那幾行就標得出來，不會進語料 |
| `hooks/complaint_learn.py` | 他一說「聽不懂」，就分析上一輪的問答，分四種原因寫進紀錄 |

## 語料在哪，為什麼不在這個 repo 裡

`copy-samples/` 底下有兩份語料，合計約 42 萬字：Vin 歷來打的中文訊息，
以及他自己寫的正式文件（研究報告、規格、簡報）約 32 萬字。
**兩份都被 `.gitignore` 擋在版控外面**，因為那是他本人的文件與私人訊息。
要重建就跑 `copy-samples/build_vin_corpus.py` 與 `extract_docs.py`。

語料只收他親手打的字。他退稿時順手打出來的 AI 句子、帶反引號貼回來的稿、
檢查程式自己的回報，重建的時候擋掉；他照原樣貼回來的 AI 句子沒有這些記號，
所以在存進去的當下就標好，重建時跳過（2026-10-04 查出三則，記在 issue #4）。

正式文件那一份非補不可：日常對話只教得會口語，教不會正式文體。
Vin 自己講過「你自己寫過的東西 —— 規格、信、簡報、Google Docs。一份抵一百則對話」。

### 語料有三種污染，不擋就會讓 AI 自己的爛句子變成「他寫過的詞」

| 污染來源 | 長什麼樣 |
|---|---|
| 他退稿時把 AI 的爛句子一起打出來，跟他的修正並排 | `AI 的爛句子 --> 他的指正` |
| 他把 AI 的整份草稿貼回去要它改 | 那整段其實是 AI 寫的 |
| 檢查程式自己印出來的回報被當成他的訊息存下來 | 機器輸出混進語料 |

清理之前，40 個他親口退掉的詞裡有 20 個被誤判成「他自己也用過」。清乾淨之後剩 14 個。

## 怎麼考語意判官

沒有考題就等於再加一個會自我感覺良好的角色。

考題兩邊都是 AI 寫的稿：壞的那幾則是他下一句就說「聽不懂」的，
好的那幾則是他親口說這段寫得好的。
第一版拿他自己打的訊息當好的那一邊，結果語意判官學會的是分辨誰寫的，不是分辨好不好。

**他當下沒說話的那幾千則標成「不知道」，不進考試。** Vin 2026-09-15 的原話：
「我沒有說好，並不代表你的文法是好範例，有可能只是我懶得說、有其他重要的事情要跟你溝通，
所以才沒提」。同一天他親手改了十三句，那十三句當下他都沒說話。

好的那幾則只有他能給，所以有一支掛勾在接：他一說這段寫得好，
`complaint_learn.py` 就把前一則存進 `approved.jsonl`。

### 兩種問法差多少

同一個判官、同一批九對考題（同一個問題下，他退掉的那一份對上他當場接受的那一份）：

| 問法 | 分對 | 分錯 | 打平手 |
|---|---|---|---|
| 各自打一個難讀的分數 | 2 對 | 2 對 | 5 對 |
| 兩份一起比，問哪一份比較難讀 | 8 對 | 0 對 | 不准打平手 |

跑法：`COPY_JUDGE_BACKEND=claude python3 copy-samples/judge_exam.py --compare --workers 3`

**一對要問兩次，爛的那一份先當 A、再當 B。** 只問一次的話，一個永遠挑 A 的判官會拿到
滿分或零分，而那不是在讀內容，是在看位置。九對裡就抓到一對是這樣，它不計分。

**「比較長的那一份是爛的」在同一批考題也對八對**，所以這份成績還不足以說它在讀內容。
兩者錯的不是同一對：唯一一對爛的比較短（494 字對 500 字），判官挑對了。

### 打分數那條路的門檻

門檻不由語意判官自己決定，由考題決定：掃過 1 到 10 分，取抓到率減打擾率最高的那一個。
成績寫進 `copy-samples/judge-score.json`。要准它擋人，四個條件要同時成立：
抓到率 ≥ 70%、每百則回話攔 ≤ 25 則、誤打他說好的 ≤ 15%，而且每一群都要問到九成的題目。
**考不過的時候連門檻也不採用**，退回程式裡的預設值，因為考不過的那一張成績單是從沒有分辨力的
一輪算出來的，照著用只會讓每一則長回話都跳出一串意見。

**好壞兩邊要是同一批題目，不然量到的是長度。** 同一個洞踩過兩次。
第一次是 2026-10-03 早上查出舊考題字數差三倍，不讀內容、只算字數就能考到
抓到 81%、誤判 0%。第二次是同一天下午：語意判官中文不到 120 字就不給分，
考試沒關掉那道地板，最短的那幾題被無聲丟掉，而「只算字數」那條基準線是拿全部的題目算的。
所以現在考試送題目一律帶 `--min 0`，基準線也改成拿判官真的打過分的那幾題算。
改考試的時候每加一道篩選，就問一次：這道篩選有沒有同時套到基準線那一邊？

| 這一群 | 哪裡來的 | 它回答什麼 |
|---|---|---|
| 他抱怨過的 | 他下一句就說聽不懂 | 抓到率 |
| 他沒說話的 | 隨機抽，代表平常的回話 | 打擾率，也就是每百則回話會攔下幾則 |
| 他親口說好的 | 他當場說這段寫得好 | 誤判率，這一群一則都不該被攔 |
| 配對題 | 他說聽不懂、我當場重寫、他說好，連在一起的三則 | 同一個問題、同一輪工作，判官分不分得出好壞 |

```bash
python3 copy-samples/build_gold.py      # 產生三群考題
python3 copy-samples/build_pairs.py     # 產生配對考題
python3 copy-samples/judge_exam.py --n 60
python3 copy-samples/judge_exam.py --pairs
COPY_JUDGE_BACKEND=claude python3 copy-samples/judge_exam.py --compare --workers 3
```

`--compare` 跑完會寫 `copy-samples/judge-pair-score.json`，**一個模型一筆**。
回話那一關只准讓那份成績單上 `pass` 成立的模型擋人，而且規範的簽章要跟現在這份對得上。
考過的是 Claude 不代表 agy 也行，而且這不是假設：**agy 考同一批九對只對 4 對，
跟丟硬幣一樣；Claude 對 8 對。** 打分數那個問法上兩個模型一樣爛，
換成兩份一起比之後只有 Claude 行 —— 換了問法它才有機會判對，但是要真的判對，還要一個夠強的模型。
改過 `judge-rubric-pair.txt` 就要重考，不重考的話那一關整個降成只提醒。

## 目前卡在哪

| 困難點 | 現況 |
|---|---|
| 打分數那個問法分不出好壞 | 1 到 10 分逐個門檻算過，差距最大的只贏 2.8 個百分點，只算字數的那條贏 10.5。換成兩份一起比，同一個判官九對分對八對 |
| 「字數」這個替代解釋還沒排除 | 「比較長的那一份是爛的」在同一批考題也對八對。兩者錯的不是同一對，但九組裡只有一組分得開這兩件事 |
| agy 用新問法也考不過 | 九對只對 4 對、錯 3 對、看位置 2 對，瞎猜機率 50%。Claude 同一批是 8 對、瞎猜機率 0.39%。所以 agy 答話的時候重寫那一關只提醒不擋。Vin 2026-10-03 決定維持只提醒，等他用一段時間、紀錄變多再看怎麼改 |
| 以前那兩張成績單都是假的 | 一張量的是字數差三倍，一張量的是兩邊不同批題目 |
| 判官用的模型會沒額度 | `agy` 額度用完會回 429。`COPY_JUDGE_BACKEND=claude` 可以改問 Claude，用的是 Vin 自己訂的額度，所以平常不開；他說看不懂之後那一關問不到 agy 的時候會自己換過去，一個出口只問一次，一次把關最多四次呼叫 |
| 存過的分數要重新付一次 | 快取的鍵含模型，而模型 2026-10-03 才釘住，所以之前那 247 題作廢 |
| 他認可過的段落只有 15 段 | 進得了考試的只有 10 段（其餘沒有「他問的那一句」），所以誤判率量不準 |
| 文件那一側沒有「他問的那一句」 | 沒有問題可比的時候，語意判官會反過來給好文件低分 |
| 語意判官會把他的口語改成公文 | 早期版本把他親手寫的六個句子全部退掉 |
